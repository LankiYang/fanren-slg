# 道途指南与 30 日引导规范

## 目标

解决玩家打开游戏后不知道“现在做什么、为什么做、做完得到什么”的问题。引导不再只覆盖开局前几分钟，而是把洞府、寻道、练兵、秘境、功法/丹药/法宝、宗门、远征、战区和好友串成一条可持续 30 天的路线。

## 三层结构

1. **开局阻断教程**：只教不点就不会的操作，包含资源、洞府升级、寻道、任务追踪器和底栏入口。
2. **功能首次引导**：玩家第一次打开系统时播放 2—3 步，说明系统目标、失败代价、资源出口和下一次上线理由。
3. **道途指南**：主城常驻一张轻量卡片，完整面板按阶段显示目标、原因、做法、直达入口、奖励和下一阶段预告。

点击任务的“去做”后进入第四层的**任务操作教程**：先完成页面跳转，再由 `GUIDE_TOURS` 按任务 id 播放阻断式步骤。每一步可以挖出唯一高亮目标，点击型步骤只允许点击高亮控件，错误区域由蒙层拦截；纯说明步骤允许点击对话框继续。任务教程有“跳过引导”，只存在于内存，不会污染旧存档或把任务误判为完成。

## 阶段路线

| 阶段 | 时间标签 | 主问题 | 主要玩法 |
|---|---|---|---|
| 开府立足 | D1—D3 | 资源从哪里来、修为怎么涨 | 洞府、四种产出、寻道、首次突破 |
| 秘境立威 | D3—D7 | 战力为什么打不赢 | 演武、三兵种克制、编队、兵损和补兵 |
| 筑基成势 | D7—D14 | 多余资源投到哪里 | 藏经阁、炼丹房、炼器阁、修士、筑基 |
| 宗门立身 | D14—D21 | 单人循环之外做什么 | 宗门、合围妖兽、远征路线、周/赛季积分 |
| 战区争雄 | D21—D30 | 地图上如何获得持续收益 | 据点、行军、战争令、驻防、好友协同 |
| 结丹争道 | D30+ | 后期每天为什么还要上线 | 远征遗物、战区榜单、主力兵种、结丹突破 |

时间标签是节奏提示，不是硬锁。阶段实际由存档进度决定，因此旧玩家刷新后会直接看到自己当前阶段。

## 数据与兼容

- `src/game/guide.ts` 是阶段、例行循环和直达路由的单一描述源。
- `Quest` 增加 `chapter`、`why`、`how` 和 `route`，目标判断仍是纯函数，领取仍然幂等。
- `GameState.journeyStartedAt` 用于显示相对天数；旧存档缺失时补当前时间，不影响任何养成数值。
- `GameState.guideFlags` 只记录跨页面动作（战区行军、驻防、好友申请/同意），旧存档默认空数组，不覆盖已有进度。
- `src/game/tutorial.ts` 的 `GUIDE_TOURS` 只描述任务操作步骤；`Store.activeGuide`/`guideStep` 是瞬时 UI 状态，不进入 `persist`，刷新后不会恢复半截蒙层。
- 新增字段必须同时出现在 `initialState`、`loadState` 和 `persist`；以后迁移到服务端时，指南判断仍可只读权威成长状态和动作事件。

## 交互约束

- 主城只显示摘要，完整解释放在可滚动的底部面板，不能遮挡建筑点击区域。
- “去做”必须直接切换到对应 tab 或建筑；不要求玩家自己在多个页面里找入口。
- “去做”跳转完成后再启动任务教程，目标页面必须先挂载；页面控件通过 `data-tut` 或稳定 class 暴露锚点，避免依赖文案定位。
- 点击型步骤必须保证高亮控件可操作；异步连接、资源不足或尚未占领据点的场景使用说明步骤，并保留跳过入口，不能把玩家锁死在不存在的目标上。
- 任务文案必须同时回答：做什么、为什么做、怎么做、完成后获得什么。
- 战区目标不能仅依赖本地模拟战功；联机动作由 `guideFlags` 记录，避免真实服务器行军后本地任务永久卡住。
- 阶段目标全部完成后仍保留 D30+ 目标，不显示“教程结束”作为内容终点。

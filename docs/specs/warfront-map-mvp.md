# 共享地图战争 MVP

## 目标

战区的主交互必须发生在共享地图上：玩家点击据点后派出一支真实行军，所有在线玩家都能看到军队沿地图移动，部队抵达目标后才由服务端结算战斗和占领。

本版本是“异步实时地图战争”MVP：前端每 900ms 拉取服务端快照并用位置过渡补足动画，服务端是唯一的兵力、行军、战斗、占领和战报权威。它不是 WebSocket 帧同步，也不把战斗胜负交给浏览器。

地图战斗与洞府养成使用同一份 `BattleProfile`。前端从本地洞府状态生成档案，服务端只接收并校验等级、修士、功法、法宝、丹药和寻道灵装等白名单字段，不接受客户端计算出的战力数字；服务端按统一公式重算行军战力、占领后的守军战力和玩家战力展示。

## 世界模型

- `WarfrontNodeDef.position` 是地图归一化坐标，`connections` 是道路连接。
- `ServerPlayer.mapPosition` 是玩家最后抵达的地图位置。
- `ServerPlayer.march` 最多同时存在一支行军，保存起点、目标、开始/到达时间、编队和策略。
- `WarfrontSnapshot.armies` 只返回仍在路上的部队，位置由服务端按时间插值。
- 据点节点显示当前宗门、守军兵力和版本号；驻军仍是据点的实际守军。

## 行军生命周期

```text
地图点击目标
  -> POST /api/warfront/march
  -> 服务端校验战争令、冷却、同宗关系、编队上限
  -> 立即扣除出征兵力，写入 march
  -> 快照返回 armies，所有玩家看到移动军队
  -> arriveAt 到达
  -> advanceWorld 结算兵种克制、策略、兵损、战功、占领
  -> 胜利进入目标据点守军；失败幸存兵力返回出发位置
  -> 生成共享战报，清除 march
```

胜利战报的首笔资源奖励进入本地洞府仓库，并由战报 ID 去重；据点的持续收益由服务端按宗门归属计算后放入 `WarfrontSnapshot.warfrontIncome`，本地产出循环读取该值。这样地图争夺会持续反哺建造、突破和养成，且不会把本地旧原型据点状态与真实联机据点叠加。

`advanceWorld` 在认证、快照和所有服务端 mutation 前执行，因此不会依赖某个玩家保持页面打开。旧的 `/api/warfront/attack` 继续保留，供旧客户端和兼容测试使用，但新前端主流程只调用 `/api/warfront/march`。

## 前端分层

- `WarfrontMap`：道路、据点、占领色、玩家位置、行军旗标和抵达倒计时。
- `WarfrontPanel`：地图命令条、编队、驻防、榜单和战报，不再用列表替代地图。
- `WarfrontBattleScene`：只演出已经由服务端返回的战报，不重新计算胜负；战报抽屉不会把用户带离地图。

## 兼容与测试

联机 schema 从 1 升至 2。读取旧 JSON 时，缺少 `mapPosition` 的玩家按宗门出生点补齐，缺少 `march` 的玩家设为 `null`；节点和旧战报保持兼容。

`sim/multiplayer.ts` 覆盖双玩家发起行军、立即扣兵、他人可见、抵达结算、占领、旧即时攻击、驻防、反攻和幂等。

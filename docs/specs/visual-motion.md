# 洞府视觉动效规格

## 目标

让玩家一眼看出洞府正在运转、资源正在产生、建筑拥有不同的修真职能。动效是表现层，不参与资源计算、升级结算或战斗胜负。

当前版本采用轻量 CSS 动效层加固定数量 Canvas 粒子池覆盖静态 WebP 建筑。它适合 Web 端和移动端，后续可以在不修改业务组件的前提下继续替换为更高保真的透明小精灵或 WebGL。

## 动效分层

```text
Scene
  建筑按钮（点击和无障碍语义）
    BuildingEffects（光晕、环、粒子、轨迹）
    建筑 WebP
    建筑状态标签
  SceneAmbientCanvas（固定粒子池、职能色彩、锚点轨迹）

TopBar
  资源图标
  资源数字滚动
  产出脉冲
  收益飘字
```

`BuildingEffects` 必须保持 `pointer-events: none`，不能截断建筑点击。它只接收建筑 key 和升级状态，不读取或修改游戏 store。

## 节奏原则

- 环境动效 2.1 至 7 秒一个周期，避免所有建筑同步闪烁。
- 粒子必须有错峰延迟和透明度变化，不能持续满屏发光。
- 资源条只做低频呼吸和图标微动；到账飘字只在实际奖励到账时出现。
- 升级中缩短粒子周期并降低饱和度，表达施工状态但不抢过“完成升级”反馈。
- `prefers-reduced-motion: reduce` 下停止循环动画，保留静态光环和数值更新。

## 后续高保真路线

1. 第一层：当前 CSS 光环、粒子、轨迹，覆盖所有建筑的运转状态。
2. 第二层：当前 Canvas 固定粒子池，按建筑职能绘制灵气、萤火、矿火、交易灵流和护宗轨迹。
3. 第三层：为聚灵阵、灵田、矿脉、坊市制作 2 至 4 帧一致性较高的透明小精灵，替换通用圆点粒子。
4. 第四层：接入更完整的 Canvas/WebGL 粒子池，统一处理视差、风向、昼夜和性能预算。
5. 第五层：建筑升级完成、境界突破、资源收取和战斗胜利使用一次性高光动画，形成明确的奖励峰值。

## 性能和兼容性

- 当前动效不新增图片请求，不引入第三方运行时。
- Canvas 粒子池最多 72 个粒子，按激活建筑数量取固定上限，不随资源产出 tick 增长。
- 只使用 `transform`、`opacity`、`filter` 和少量阴影，避免逐帧修改布局属性。
- Canvas 只更新自己的绘图缓冲区，不触发 React 组件树逐粒子重渲染；粒子核心按四相位切换圆点、菱形、方晶和环光，形成轻量精灵帧感。
- 资源数值和奖励动画继续使用定时器兜底，不能依赖后台标签页一定触发 `animationend`。

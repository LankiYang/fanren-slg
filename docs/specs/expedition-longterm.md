# 天机远征长期玩法规格

## 目标

为单城建造与练兵提供一个能连续参与 30 天的主动循环。玩家每天不是只领取资源，而是要在路线、战斗编队、风险收益和长期兑换之间做决定。

远征属于本地养成侧的第一版长期玩法，战斗规则复用 `battlePower`、兵种克制、出战编队和兵损逻辑；未来迁移到服务端时，保留相同的节点快照和战报结构即可替换结算权威。

## 循环结构

```text
每日/每 8 小时恢复远征令
  -> 进入当天主题地图
  -> 当前层二选一路线
  -> 选择稳妥或压榨路线
  -> 战斗/采集/护送/事件/首领结算
  -> 资源、积分、远征币、兵损进入养成循环
  -> 周里程碑与 28 天游历奖励
  -> 远征商店兑换永久遗物
```

- 远征令上限 3 枚，每 8 小时恢复 1 枚。
- 地图有 5 层：前 4 层每层 2 个节点，终点 1 个首领节点。
- 每层只可选择 1 条路线，选中的节点结算后进入下一层。
- 每日 3 枚令不足以完成五层，因此未完成地图跨午夜保留；首领击破后若仍有令，立即生成同主题下一张地图，避免行动令空转。
- 地图主题按 7 天轮换，28 天组成一个远征赛季；日期、路线和敌人使用稳定 seed，不依赖 `Math.random()`。

## 节点与决策

| 节点 | 主要作用 | 战斗/资源关系 |
|---|---|---|
| 破阵 | 复用兵种克制战斗 | 使用出战编队、修士、功法、丹药、法宝和兵损 |
| 采灵 | 直接补充某类资源 | 给灵田、矿脉和仓库提供额外消耗出口 |
| 护送 | 资源与远征币的中等收益 | 压榨路线会产生小额兵损，推动持续练兵 |
| 天机 | 稳妥拿遗物或压榨高收益 | 风险选择提高奖励，但失败会产生兵损且不推进路线 |
| 首领 | 当前地图最高奖励 | 使用首领级敌军战力，必须在前四层完成后开启 |

稳妥路线奖励倍率为 1，压榨路线为 1.35；压榨战斗提高进攻倍率但会提高兵损。战斗胜负在 Store 内结算，前端战报只播放冻结快照，不重新计算胜负。

## 失败与代价

远征令是一次行动的硬成本，任何已开始的节点都会消耗 1 枚远征令。所有战斗使用统一兵损函数：胜利是有限兵损，失败是更高兵损；损失从冻结的出战编队扣除，并同步修正玩家当前编队。

- 破阵/首领失败：节点保持未完成，路线层数不变，资源、积分和远征币均为 0，可用下一枚远征令重新挑战。
- 压榨采灵/护送/天机：使用稳定 seed 判定风险，失败时产生较高小额兵损，节点保持未完成，奖励为 0。
- 成功节点：正常推进一层，按选择发放资源、积分和远征币；即使胜利也会显示本次行动的兵损。
- 失败报告必须明确显示“行动令、兵损、路线未推进、奖励为 0”，不能只显示一句失败文案。

这样失败有真实机会成本，但不会永久锁死主线：补充兵力后仍能用下一枚远征令重试，且失败不会摧毁已经完成的前置层。

## 长期目标

- 周积分里程碑：300 / 720 / 1280，领取远征币和四资源奖励。
- 28 天游历里程碑：900 / 2400 / 4600 / 7200，领取远征币、资源和遗物层数。
- 远征商店：灵脉宝匣、星图残卷、破阵战旗、聚灵香炉。
- 遗物效果：星图提高积分获取，战旗提高远征战斗战力，香炉提高远征资源奖励；每种最多 3 层。
- 30 天模拟目标：至少 10 张地图、90 次行动、5 个主题、所有节点类型可见、至少一轮赛季可达到最高积分档，并能购买完整遗物套装。

## 状态与迁移

`GameState` 保存以下远征状态：

- 当前日历日、地图所属日期、地图轮次、远征令及恢复时间。
- 当前推进层、节点快照、赛季积分、本周积分和远征币。
- 周/赛季已领取奖励、遗物等级和商店购买次数。

旧的 `fanren-slg-save-v2` 没有这些字段时，`loadState()` 使用初始远征地图补齐；旧地图不会覆盖已有洞府、兵力或资源。远征第一版继续使用 localStorage，和服务端权威的共享战区边界保持分离。

## 演出验收

1. 点击路线节点后，选择稳妥/压榨会明确影响按钮文案和结算倍率。
2. 破阵或首领会播放四幕攻防：列阵、我方推进、敌方反击、结果揭晓；动画只读取 `ExpeditionReport`。
3. 非战斗节点会播放奖励揭晓态，结果、积分、远征币和兵损分层出现；压榨路线失败时显示失败惩罚并保留节点。
4. 刷新页面后，地图推进、远征令、积分、遗物和商店购买次数保持不变。
5. `prefers-reduced-motion: reduce` 下关闭循环漂浮和路线脉冲，保留结算文字与数值。

## 验证命令

```bash
npm run expedition
npm run check
```

`sim/expedition.ts` 与线上使用同一份 `src/game/expedition.ts` 规则，专门检查 30 天行动覆盖和内容轮换；`npm run check` 还会执行 TypeScript、数值审计、基础节奏模拟、战区和多人自测。

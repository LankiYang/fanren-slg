# PvE 失败代价规格

## 目标

秘境推图和天机远征必须让“挑战更高难度”成为有判断的行为，而不是可以无成本反复点击的演示按钮。失败要有可见的兵力损耗和机会成本，同时不能因为一次失败永久卡死主线。

## 统一规则

`src/game/penalty.ts` 提供统一的战斗兵损函数：

- 胜利按敌我战力比产生有限兵损，默认损耗区间低于失败。
- 失败按敌我战力比产生更高兵损，并限制最高损耗，避免单次清空全部部队。
- 兵损只从本次实际出战编队扣除，扣除后编队自动裁剪到现存兵力。
- 失败不发放首通/节点奖励，不推进对应关卡或远征路线。

## 秘境

秘境每次挑战不额外消耗挑战券，但胜负都会消耗实际兵力。失败保留当前关卡，玩家可以补兵、调整克制编队后再次挑战；成功推进关卡并发放首通奖励，但同样显示兵损。这样资源、练兵、编队和推图形成闭环，而不是只看一个战力数字。

## 天机远征

远征令是每次节点行动的机会成本。战斗失败或压榨路线的非战斗风险失败均扣 1 枚远征令、产生兵损、不给节点奖励并保留节点；下一次行动可以重新挑战。成功才推进层数、结算积分和远征币。风险使用稳定 seed，刷新页面不会改写结果。

## 前端反馈

所有失败结果至少展示：兵损数量、消耗的行动/远征令、未推进提示、奖励为 0，以及下一步“补兵/调整编队后再战”的建议。动画只读取已经结算的报告，不参与数值判断。

## 验证

- `npm run stage`：验证秘境失败兵损、关卡不推进、补兵后可重试。
- `npm run expedition`：验证 30 天远征循环与内容出口。
- `npm run check`：包含 TypeScript、数值审计、战区、多人、远征、秘境和寻道自测。

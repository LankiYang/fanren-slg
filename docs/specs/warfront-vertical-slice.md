# 战区争夺垂直切片

## 目标

将现有的洞府养成原型改造成轻量 SLG 的可验证核心：玩家经营洞府以训练部队，进入赛季秘境夺取有限据点，与敌对势力竞争战功和持续产出。

当前交付是可运行的异步多人战区版本，目的在于验证战前决策、兵损、驻防协作和据点收益是否能让养成循环服务于争夺。它不是实时 PvP，也不得对外表述为实时战斗。

## 本轮范围

- 六个共享据点，初始由秘境守军或其他玩家宗门占领。
- 三种出征策略：强攻、谨慎、奇袭。策略在战力和兵损之间取舍。
- 复用已有的兵种克制、出征编队、修士、法宝与丹药战力计算。
- 胜利后获得首夺资源、据点每秒产出与赛季战功；失败和胜利都会造成兵损。
- 出征消耗战争令，战争令按时间恢复；另有短整备冷却，避免无限点击试错。
- 占领后的幸存兵力会成为真实守军，同宗玩家可以派遣援军或撤回自己的援军；驻军上限为 360。
- 服务端提供个人榜、宗门榜和攻击者/防守者战报；前端每 3 秒轮询共享状态。
- 地图命令区紧贴地图画布，选中据点后立即可见；编队滑杆按需展开，命令区支持收起，不依赖滚动到页面底部确认。

## 关键规则

| 规则 | 说明 |
| --- | --- |
| 出征资格 | 需已建演武场且编队至少有一名部队。 |
| 战力 | 现有 `battlePower` 先按兵种克制结算，再乘策略系数。 |
| 胜负 | 有效战力大于等于据点守军战力即胜。 |
| 兵损 | 按敌我战力比、胜负和策略计算，直接从出征编队扣除。 |
| 占领 | 胜利后节点归我方；已占领节点不能重复攻击。 |
| 据点产出 | 节点收入追加到 `computeRates`，不叠加境界或丹药倍率。 |

## 领域边界

- `src/game/warfront.ts`：节点、策略、初始占领和据点产出等纯领域数据。
- `src/game/store.ts`：单机战区兼容逻辑；联机战区由 `src/online` 调用服务端命令响应。
- `src/ui/WarfrontPanel.tsx`：地图、策略选择、编队和战报展示，不直接修改数值状态；地图下方先呈现选中据点的战术、战力和派出按钮，详细编队可折叠。

## 联机替换条件

继续扩展到实时 PvP 前，客户端不再拥有节点归属、资源结算和兵损的写权限。服务端需要提供：

1. 赛季、战区、节点、宗门、部队和战斗快照的持久化模型。
2. 幂等的出征命令与事务锁，避免同一节点并发占领。
3. 确定性战斗种子、输入快照和可重放战报。
4. 节点占领、行军到达、冷却和赛季结算的任务队列。
5. 基于服务端积分的个人、宗门和区域排行榜。

## 验证指标

- 新玩家完成演武场与首次出征后，至少能解释一次胜负来自何种克制或策略。
- 测试者会主动改动编队或策略，而非只追求总战力。
- 玩家会因兵损、据点产出和榜单位置形成下一次上线目标。
- 若上述行为不出现，应先迭代战斗与据点价值，不应继续堆叠养成系统。

## 联机验收

1. 打开两个浏览器标签页，分别进入战区，得到两个玩家和不同宗门。
2. A 攻下迷雾关；B 刷新或等待轮询后看到据点版本、宗门和驻守玩家改变。
3. B 以克制兵种反攻；A 在战报中看到自己作为防守方。
4. 对同一请求重复提交，玩家兵力和战功保持不变。
5. A 派援军驻防后，个人兵力下降、据点版本和守军战力上升；撤回后兵力恢复。
6. 发起一次联机出征，战斗演出推进到结算态；返回战区后战争令减少 1。
